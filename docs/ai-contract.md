# AI-контракт v2: backend ↔ ai_service

`ai_service/` — HTTP-обёртка над кодом AI-команды. Их файлы скопированы без изменений, кроме отмеченной правки `no_pathology` в `analysis.py`:
- `analysis.py` — промпт, проверка ответа (`validate`), ссылки на источники (`attach_sources`);
- `guidelines.py` и `guidelines/*.json` — справочник «находка → действие» из клинических рекомендаций;
- `bft_templates.*` — шаблоны протоколов БФТ;
- `b2c.py` — объяснение для пациента.

Модель — LLM через Hugging Face Inference API (`HF_TOKEN`, `MODEL` в `config/ai_service.env`).

## 1. Анализ протокола: `POST /ai/v1/analyze`

### Запрос

```json
{
  "request_id": "req_01J9…",
  "study_id": "st_01J9…",
  "study_type": "ct",
  "body_region": "chest",
  "report_text": "Описание: Грудная аорта: наибольшее значение диаметра восходящей части грудной аорты: 40 мм. Очаги и образования легких: не обнаружены.\nЗаключение: Дилатация восходящей аорты.",
  "patient_context": { "age": 58, "sex": "m" }
}
```

- `report_text` — поля DICOM SR дословно, в формате AI-команды: «Описание: Поле: значение. …», затем заключение, если есть. ФИО в модель не передаётся.
- `study_type` + `body_region` выбирают шаблон БФТ и справочник:

| study_type + body_region | Тип у модели |
|---|---|
| `ct` + `chest` | КТ ОГК |
| `xray` + `chest` | РГ/ФЛГ ОГК |
| `mammography` + `breast` | маммография |
| `ct` + `head` | КТ ГМ — справочник без шаблона БФТ |

Полный пример — [../examples/ai_request.json](../examples/ai_request.json).

### Что делает ai_service

Алгоритм повторяет `test_of_models.ask()` AI-команды:

1. В промпт попадают шаблон БФТ и **записи справочника, найденные по словам протокола**.
2. Модель отвечает JSON. Если ей не хватило справочника (`need_full_guidelines: true`), делается второй запрос — с полным справочником.
3. `validate(parsed, study_type)` — проверка кодов и структуры. Замечания уходят в `warnings`.
4. `attach_sources` — по id записей справочника подставляются документ и страницы (`source_refs`). Ссылки, которых в справочнике нет, попадают в `unconfirmed_sources`.
5. К каждому документу дописывается `url` официальной страницы. Это рубрикатор клинических рекомендаций Минздрава, методички НПКЦ ДиТ и т. п. Адреса проверены вручную — `ai_service/source_urls.json`. У PDF к адресу добавляется `#page=N`.

### Ответ

```json
{
  "request_id": "req_01J9…",
  "model": { "name": "Qwen/Qwen3-4B-Instruct-2507", "version": "hf-inference" },
  "options": [
    {
      "type": "additional_research",
      "recommended": true,
      "items": [
        {
          "code": "ct_angiography",
          "reason": "Дилатация восходящей аорты 40 мм",
          "timing": "через 6–12 месяцев",
          "sources": ["kr_aorta_followup"],
          "source_refs": [{ "text": "КР «Аневризмы грудной и торакоабдоминальной аорты» (Минздрав, 2025), стр. 89",
                            "pages": "89", "url": "https://cr.minzdrav.gov.ru/view-cr/919_1" }],
          "unconfirmed_sources": []
        }
      ],
      "rationale": "Расширение восходящей аорты — контроль размеров по КР."
    },
    { "type": "specialist_consult", "recommended": false, "items": [{ "code": "cardiologist", "reason": "…" }], "rationale": "…" }
  ],
  "reasons": [{ "code": "aorta_dilation", "label": "Дилатация восходящей аорты 40 мм" }],
  "guidelines_mode": "по словам протокола",
  "warnings": []
}
```

| Поле | Значение |
|---|---|
| `options[]` | 1–3 варианта маршрута, ровно один `recommended`. `type`: `repeat_appointment`, `specialist_consult`, `additional_research`, `urgent_hospitalization`, `no_pathology`. Последние два — без пунктов |
| `items[].code` | код специалиста или исследования из справочника клиники (`GET /api/v1/dictionaries`) — к нему можно записать пациента |
| `items[].timing` | срок по клиническим рекомендациям, если есть |
| `source_refs` / `unconfirmed_sources` | подтверждённые справочником документы и страницы / ссылки модели, которых в справочнике нет. Пункт без источников — «предложение модели» |
| `reasons[]` | находки в протоколе, от главной к второстепенной |
| `guidelines_mode` | какой справочник видела модель: «по словам протокола», «весь справочник», «весь справочник по запросу модели» |

Уверенности (`confidence`) у модели нет — интерфейс показывает порядок вариантов. Полный пример — [../examples/ai_response.json](../examples/ai_response.json); это иллюстрация формата, а не реальный ответ модели.

### Как backend разбирает ответ (`backend/app/ai/contract.py`)

- **Строго.** Нужны хотя бы один вариант известного типа и непустые `reasons`. Иначе — статус «AI не отвечает», врач работает без AI.
- **Мягко.** Неизвестные типы и коды отбрасываются, лишние пункты у «экстренной госпитализации» и «патологии не выявлено» убираются, чужой `request_id` заменяется своим. Если основных вариантов нет или их несколько, основным становится первый. Всё это записывается в предупреждения, они видны врачу.
- **Что выводится из ответа:**
  - `recommendation` — тип основного варианта;
  - `details` — коды его пунктов: на них держатся предвыбор в форме решения, согласие с AI и совпадение деталей;
  - все варианты сохраняются целиком.
- **Старые форматы** v1 (`confidence`, `ranked_options`, `details`) и v1.3 (`options_order`) тоже принимаются — для тестов и ручной загрузки JSON.

### Ошибки

- `503` — сервис не настроен (нет `HF_TOKEN` / `MODEL`).
- `502` — модель недоступна или ответила не JSON. В `detail` — короткая причина: например, «закончились кредиты Hugging Face (HTTP 402)».
- Backend ждёт ответа до `AI_TIMEOUT_S` = 120 с. При ошибке — статус `ai_failed` и кнопка «Отправить повторно»: не чаще раза в 10 с.

## 2. Объяснение пациенту: `POST /ai/v1/explain`

```json
{ "request_id": "req_…", "study_type": "ct", "body_region": "chest",
  "description": "Грудная аорта: …", "conclusion": "Дилатация восходящей аорты." }
```
→
```json
{ "summary": "…простым языком…", "explanations": [{ "term": "Дилатация", "explanation": "расширение" }] }
```

Промпт AI-команды запрещает модели ставить диагнозы, назначать лечение и формулировать дальнейшие шаги. Что делать дальше, пациент узнаёт из решения врача — это шаблонный текст. Backend запрашивает объяснение один раз, когда пациент открывает карточку. При сбое показывается «Объяснение пока недоступно».
