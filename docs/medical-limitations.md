# Ограничения и особенности медицинской тематики

## Статус решения

- **Демонстрационный прототип** для хакатона. Не является медицинским изделием, не зарегистрирован, не предназначен для клинического применения.
- **Данные синтетические.** ФИО, телефоны, почты и протоколы вымышлены или составлены по открытым шаблонам. Реальные персональные и медицинские данные не использовались.

## Роль AI

- **AI — подсказка, решение за врачом.**
  - Врач видит варианты модели и выбирает маршрут сам.
  - Решение можно принять и без AI: не дожидаясь ответа или при сбое.
  - Согласие с AI фиксируется и измеряется — для оценки модели, а не для контроля врача.
- **Пациент не получает ответ модели как назначение.**
  - Что делать дальше, пациенту сообщает шаблонный текст по решению врача.
  - Модель только объясняет результат исследования простым языком. По промпту AI-команды она не ставит диагнозов, не назначает лечение и не формулирует дальнейших шагов. Под объяснением на сайте стоит: «Решение о лечении принимает врач».
- **Прозрачность.**
  - У каждого пункта рекомендации — документ и страница клинических рекомендаций со ссылкой на официальную страницу.
  - Ссылка, не подтверждённая справочником, помечается.
  - Пункт без источника отмечен как «предложение модели, не из документа».
- **Модель может ошибаться**: LLM общего назначения, не обученная и не валидированная на клинических данных. Справочник покрывает ограниченный набор находок.

## Что поддерживается

- **Типы исследований:**
  - КТ органов грудной клетки;
  - рентгенография / флюорография органов грудной клетки;
  - маммография;
  - КТ головного мозга.

  Только те, для которых у AI-команды есть шаблон протокола БФТ или справочник клинических рекомендаций.
- **Только описание находок из протокола.** Заключение рентгенолога в систему не берётся — AI делает вывод по находкам сам; если ключевой вывод (например, категория BI-RADS) есть только в заключении, модель его не увидит. Изображения не анализируются.
- **Справочник** собран AI-командой по клиническим рекомендациям Минздрава и методическим рекомендациям НПКЦ ДиТ ДЗМ: Lung-RADS, BI-RADS, тактика при инциденталомах и др. Пока это **черновик**: записи ещё не проверены врачом (поле `verified_by` в `ai_service/guidelines/sources.json`). Страницы указаны по нумерации PDF-файла.

## Безопасность пациента

- **Экстренная госпитализация.**
  - Выбирается только отдельно, без других направлений.
  - Пациенту во все каналы уходит срочное сообщение «обратитесь в стационар; при ухудшении — 103».
  - Запись не требуется, кейс закрывается.
  - В очереди врача такие исследования отмечены красным и стоят сверху.
- **«Патологии не выявлено»** — тоже только отдельно: кейс закрывается без записи.
- **Напоминания:** раз в неделю, до трёх раз, пока пациент не записался по всем направлениям и не отказался. Врач может напомнить сразу.

## Персональные данные

- **В SMS и email** нет медицинских сведений — только факт готовности результата и ссылка в личный кабинет. В SMS — даже без имени.
- **Во внешнюю LLM** (Hugging Face Inference API) уходит текст протокола, возраст и пол. ФИО и контакты не передаются. В реальной эксплуатации нужна модель в контуре клиники или договор с провайдером по 152-ФЗ.
- **Хранилище — в памяти процесса**, без шифрования и резервных копий: данные пропадают при перезапуске. Для эксплуатации нужны СУБД, журналирование доступа и защищённое хранение по требованиям к медицинским информационным системам.
- **Аутентификация демо-уровня:** JWT, общий пароль демо-аккаунтов `demo`. Для эксплуатации нужна интеграция с ЕСИА или учётными записями МИС.

## Доступность

- **Время ответа.** Hugging Face Inference API отвечает 30–60 с.
- **Недоступность модели.** Сервис бывает недоступен: лимиты, закончились кредиты (402). Тогда исследование показывает «AI не отвечает», а повторная отправка ограничена разом в 10 с.
- **Масштаб.** Backend — один процесс с хранилищем в памяти. Его масштаб — демонстрация и небольшое отделение (см. [load-testing.md](load-testing.md)), а не сеть клиник.
